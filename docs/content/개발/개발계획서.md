[[기획서]]에서 정의한 기능은 대부분 구현되어 있으며, 코드는 Turborepo
모노레포 + FSD(Feature-Sliced Design) 구조로 정리되어 있습니다. 백엔드
배포는 Render로 전환되었고 상품 이미지는 Cloudflare R2에 업로드하는
방식으로 바뀌었으며, 관리자 인증(공유 비밀번호 + 세션)도 추가됐습니다.
다음 우선순위는 결제 연동 여부 결정과 테스트 도입입니다.

## 현재 아키텍처

### 모노레포 구조
- `apps/frontend` — Next.js(App Router) 키오스크 화면
- `apps/backend` — Express + MongoDB REST API 서버
- `packages/types` — 프론트/백엔드가 공유하는 계약 타입(Product, Order,
  CreateOrderInput 등)
- `packages/ui`, `packages/eslint-config`, `packages/typescript-config` —
  공용 설정/컴포넌트

### 프론트엔드 (FSD)
`apps/frontend/src/`가 다음 레이어로 구성됩니다.
- `app` — Next.js 라우팅, 각 `page.tsx`는 `views/` 슬라이스를 조립만 함
- `views` — 라우트별 화면 조합 (`home`, `admin`). 원래 FSD 표준 명칭은
  `pages`이지만, Next.js App Router가 `pages/` 디렉터리를 레거시 Pages
  Router로 인식해 라우팅 충돌이 나기 때문에 이 프로젝트에서는 `views`로
  씁니다.
- `widgets` — `product-list`, `order-summary`, `add-product-form`(이미지
  파일을 선택하면 백엔드에 업로드하고 반환된 R2 공개 URL을 미리보기와 함께
  씀), `manage-product-list`
- `features` — `cart`(장바구니 담기/주문 제출), `product-management`(메뉴
  등록/삭제), `admin-auth`(관리자 로그인/로그아웃, 세션 확인)
- `entities/product` — 상품 CRUD API와 `ProductCard` UI
- `shared` — 공용 axios 인스턴스(`shared/api`), API base URL 설정
  (`shared/config`)

상태 관리는 Zustand(`features/cart`, `features/product-management`)를
사용합니다.

### 백엔드
- Express 5 + Mongoose, TypeScript로 작성
- REST 엔드포인트: `GET/POST /api/products`, `DELETE /api/products/:id`,
  `POST /api/orders`, `POST /api/uploads`(이미지 파일을 Cloudflare R2에
  업로드하고 공개 URL 반환), `GET /health`(DB에 접근하지 않는 가벼운
  헬스체크 — Render 자체 헬스체크와 무료 티어 슬립 방지용 외부 핑에 사용),
  `POST /api/admin/login`/`GET /api/admin/session`/`POST /api/admin/logout`
  (관리자 로그인/세션 확인/로그아웃)
- `packages/types`의 `CreateOrderInput`, `UploadImageResponse`,
  `AdminLoginInput`, `AdminSessionResponse`를 프론트엔드와 함께 사용해
  요청/응답 계약을 공유
- Cloudflare R2 연동은 `src/lib/r2Client.ts`(`@aws-sdk/client-s3` 기반)에서
  담당하며, `multer`로 업로드된 파일을 메모리에 받아 R2로 전달
- 관리자 인증은 `express-session` + `connect-mongo`(기존 `MONGO_URI`
  재사용) 기반 세션이며, `src/middleware/requireAdmin.ts` 미들웨어가
  `POST/DELETE /api/products`, `POST /api/uploads`를 보호합니다. 세션
  쿠키를 프론트엔드(Vercel)와 주고받기 위해 CORS를 `FRONTEND_ORIGIN` 단일
  오리진 + `credentials: true`로 설정했습니다 — [[관리자인증인가]] 참고.

## 다음 우선순위 로드맵

아래 항목 중 실제 작업을 시작하는 항목은 `docs/AGENTS.md`의 SDD 워크플로우에
따라 LeanSpec으로 개별 스펙(`docs/specs/`)을 만들고 진행 상태를 추적합니다.
이 문서는 우선순위 개요만 담고, 항목별 상세 설계/작업 분해는 해당 스펙에
기록합니다.

1. **결제 연동 여부 결정** (최우선) — 주문 생성까지만 구현되어 있어, 실제
   결제 수단을 붙일지 매장에서 별도 결제할지 먼저 결정이 필요합니다.
2. **주문 상태 흐름 설계** — 접수/준비중/완료 등 상태 전이가 필요한지
   검토합니다.
3. **테스트 도입** — 현재 프론트엔드/백엔드 모두 자동화된 테스트가
   없습니다. 주문/재고 관련 로직부터 우선 커버합니다.
4. **배포 파이프라인 정비** — 배포 대상은 Vercel(frontend) / Render
   (backend, 무료 티어)로 전환 완료했고 슬립 방지용 헬스체크(`GET
   /health`)도 붙어 있습니다. 남은 일은 환경변수 정리(`NEXT_PUBLIC_API_URL`,
   `MONGO_URI`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`,
   `R2_BUCKET_NAME`, `R2_PUBLIC_URL`, `ADMIN_PASSWORD`, `SESSION_SECRET`,
   `FRONTEND_ORIGIN`)와 프론트/백엔드 CI 연동입니다 (현재
   `.github/workflows/`에는 `docs/` Quartz 배포 워크플로만 있음).
   **`ADMIN_PASSWORD`/`SESSION_SECRET`/`FRONTEND_ORIGIN`은 아직 Render에
   등록되지 않았습니다 — 등록 전까지는 운영 환경에서 관리자 로그인이
   동작하지 않습니다(단, 쓰기 API 보호 자체는 그대로 유지됩니다).**
5. **Tailwind 설정 정리** — 루트 `tailwind.config.ts`가 앱별 공용 설정
   패키지(`packages/config`) 없이 단독으로 존재합니다. 앱이 늘어나면
   통합을 검토합니다.
6. **관리자 역할 구분/감사 로그 검토** — 현재는 공유 비밀번호 하나로만
   인증하며 점주/직원 구분이나 조작 이력이 없습니다([[관리자인증인가]]
   참고). 필요해지면 별도 스펙으로 착수합니다.
