[[기획서]]에서 정의한 기능은 대부분 구현되어 있으며, 코드는 Turborepo
모노레포 + FSD(Feature-Sliced Design) 구조로 정리되어 있습니다. 다음
우선순위는 보안(관리자 인증)과 결제 연동 여부 결정, 테스트 도입입니다.

## 현재 아키텍처

### 모노레포 구조
- `apps/frontend` — Next.js(App Router) 키오스크 화면
- `apps/backend` — Express + MongoDB REST API 서버
- `packages/types` — 프론트/백엔드가 공유하는 계약 타입(Product, Order,
  CreateOrderInput 등)
- `packages/ui`, `packages/eslint-config`, `packages/typescript-config` —
  공용 설정/컴포넌트

### 프론트엔드 (FSD)
`apps/frontend/src/`가 다음 레이어로 구성됩니다.
- `app` — Next.js 라우팅, 각 `page.tsx`는 `views/` 슬라이스를 조립만 함
- `views` — 라우트별 화면 조합 (`home`, `admin`). 원래 FSD 표준 명칭은
  `pages`이지만, Next.js App Router가 `pages/` 디렉터리를 레거시 Pages
  Router로 인식해 라우팅 충돌이 나기 때문에 이 프로젝트에서는 `views`로
  씁니다.
- `widgets` — `product-list`, `order-summary`, `add-product-form`,
  `manage-product-list`
- `features` — `cart`(장바구니 담기/주문 제출), `product-management`(메뉴
  등록/삭제)
- `entities/product` — 상품 CRUD API와 `ProductCard` UI
- `shared` — 공용 axios 인스턴스(`shared/api`), API base URL 설정
  (`shared/config`)

상태 관리는 Zustand(`features/cart`, `features/product-management`)를
사용합니다.

### 백엔드
- Express 5 + Mongoose, TypeScript로 작성
- REST 엔드포인트: `GET/POST /api/products`, `DELETE /api/products/:id`,
  `POST /api/orders`
- `packages/types`의 `CreateOrderInput`을 프론트엔드와 함께 사용해 주문
  생성 요청 계약을 공유

## 다음 우선순위 로드맵

1. **관리자 인증 추가** (최우선) — `/admin`이 현재 무인증 상태([[기획서]]의
   "알려진 제약" 참고). 로그인/세션 또는 최소한의 접근 제어가 필요합니다.
2. **결제 연동 여부 결정** — 주문 생성까지만 구현되어 있어, 실제 결제
   수단을 붙일지 매장에서 별도 결제할지 먼저 결정이 필요합니다.
3. **주문 상태 흐름 설계** — 접수/준비중/완료 등 상태 전이가 필요한지
   검토합니다.
4. **테스트 도입** — 현재 프론트엔드/백엔드 모두 자동화된 테스트가
   없습니다. 주문/재고 관련 로직부터 우선 커버합니다.
5. **배포 파이프라인 정비** — 배포 대상은 Vercel(frontend) / Railway
   (backend)로 정해져 있으나, 환경변수(`NEXT_PUBLIC_API_URL`,
   `MONGO_URI`) 정리와 CI 연동이 아직 없습니다.
6. **Tailwind 설정 정리** — 루트 `tailwind.config.ts`가 앱별 공용 설정
   패키지(`packages/config`) 없이 단독으로 존재합니다. 앱이 늘어나면
   통합을 검토합니다.

  주고받는지 명시할 것
- UI 변경은 실제 화면(dev 서버)에서 정상 동작을 확인할 것
