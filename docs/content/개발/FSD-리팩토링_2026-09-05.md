# FSD 리팩토링 (2026-09-05)

[[index]]에 정리된 CLAUDE.md의 FSD(Feature-Sliced Design) 규칙에 맞춰
프론트엔드/백엔드 전체를 재구성한 기록입니다.

## 배경
CLAUDE.md 보일러플레이트를 프로젝트에 도입하면서, 기존 코드가 규칙과 어긋나는
부분(FSD 레이어 부재, API 호출 중복, `@owner` 태그 부재 등)을 정리했습니다.

## 변경 사항
- [x] `apps/frontend`를 `src/` 하위 FSD 레이어(app, views, widgets, features,
  entities, shared)로 재구성
  - FSD의 "pages" 레이어는 Next.js App Router의 `pages/` 디렉터리 라우팅
    감지와 이름이 충돌해 `views/`로 명명함. CLAUDE.md 원문의 "App Router만
    쓰므로 이름이 겹치지 않는다"는 전제는 실제 빌드에서 충돌이 확인되어
    틀린 것으로 판단, 이 프로젝트에서는 `views/`를 사용
- [x] `entities/product` 신설 — 상품 CRUD API(`getProducts`/`createProduct`/
  `deleteProductById`)를 단일화해 cart/product-management/product-list
  3곳에 흩어져 있던 axios 호출 중복 제거
- [x] `shared/api`(공용 axios 인스턴스), `shared/config`(API_BASE_URL) 신설
- [x] `packages/types`에 `CreateOrderInput`/`CreateOrderItemInput` 추가 —
  프론트엔드와 백엔드가 주문 생성 요청 계약을 공유
- [x] `apps/backend`를 JavaScript(CommonJS)에서 TypeScript로 전환,
  `@repo/types`/`@repo/typescript-config` 재사용
- [x] 이번 리팩토링에서 손댄 모든 코드 파일에 `// @owner: ai` 태그 부여
  (기존에는 태그가 전혀 없었음 — 사용자 요청으로 예외적으로 일괄 부여)

## 검증
- `apps/frontend`: `tsc --noEmit`, `next build` 통과 (`/`, `/admin` 라우트
  정상 생성)
- `apps/backend`: `tsc --noEmit`, `tsc` 빌드 후 `node dist/index.js` 기동
  확인 (MongoDB Atlas 연결은 샌드박스 네트워크 제약으로 미검증 — 라우트
  레이어 자체는 정상 응답)

## 하지 않은 것 (후속 검토 필요)
- `packages/config/`로 Tailwind 설정 통합 — 이번에는 루트
  `tailwind.config.ts`의 content 경로만 새 구조에 맞게 수정함
- Quartz 5 빌드 도구 자체 설치 — 이 문서 폴더 구조만 준비함
- `/admin` 페이지 인증/인가 추가
