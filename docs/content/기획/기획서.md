메이드 카페 매장에서 고객이 직접 메뉴를 조회·주문하고, 매장 관리자가 메뉴를
등록·삭제할 수 있는 무인 키오스크 서비스입니다. 현재 고객 주문 흐름과 관리자
메뉴 관리 흐름의 핵심 기능은 구현되어 있으나, 결제 연동과 관리자 인증은 아직
없습니다.

## 배경 및 목적

카페 사장님과 고객 모두를 위한 키오스크 서비스입니다. 고객은 매장 내
키오스크(또는 화면)에서 메뉴를 둘러보고 주문을 담아 제출하고, 매장 관리자는
별도의 관리자 화면에서 실시간으로 메뉴를 추가·삭제합니다.

## 사용자

### 고객
- 매장에 방문해 키오스크 화면(`/`)에서 메뉴를 탐색하고 주문하는 사람.
- 별도 로그인 없이 바로 이용합니다.

### 매장 관리자
- 관리자 화면(`/admin`)에서 메뉴(상품)를 등록·삭제하는 매장 운영자.
- 현재는 별도 로그인 절차 없이 URL만 알면 접근 가능합니다 (아래 "알려진
  제약" 참고).

## 핵심 사용자 흐름

### 고객: 메뉴 조회 → 주문
1. 키오스크 첫 화면(`/`)에서 전체/커피/에이드/디저트 카테고리로 메뉴를
   필터링합니다.
2. 원하는 메뉴 카드를 클릭하면 장바구니에 담깁니다. 이미 담긴 메뉴를 다시
   클릭하면 수량이 1 증가합니다.
3. 화면 오른쪽 주문 목록에서 담긴 메뉴와 총 금액을 확인합니다.
4. "주문하기"를 누르면 주문이 서버에 제출되고, 성공 시 장바구니가
   비워집니다. 실패하면 안내 메시지만 뜨고 장바구니 내용은 유지됩니다.

### 관리자: 메뉴 관리
1. 관리자 화면(`/admin`)에서 메뉴 이름·가격·이미지 URL·카테고리를 입력해
   새 메뉴를 등록합니다.
2. 필수 항목이 비어 있으면 안내 메시지가 뜨고 제출되지 않습니다.
3. 등록에 성공하면 폼이 초기화되고 메뉴 목록에 즉시 반영됩니다. 실패하면
   폼 입력값은 유지된 채 에러 메시지만 뜹니다.
4. 메뉴 목록에서 "삭제"를 누르면 확인창을 거쳐 메뉴가 삭제됩니다.

## 기능 요구사항

### 고객 화면 (`/`)
- 메뉴 목록 조회 (카테고리: 전체/커피/에이드/디저트)
- 장바구니 담기 / 수량 자동 증가
- 장바구니 총액 계산
- 주문 제출, 제출 중 로딩 상태 표시

### 관리자 화면 (`/admin`)
- 메뉴 등록 (이름, 가격, 이미지 URL, 카테고리)
- 메뉴 목록 조회
- 메뉴 삭제 (삭제 전 확인)

## 데이터 모델 개요

- **상품(Product)**: 이름, 가격, 이미지 URL, 카테고리(`coffee` | `ade` |
  `dessert`)
- **장바구니 아이템(CartItem)**: 상품 정보 + 수량. 클라이언트 상태로만
  존재하고 서버에 저장되지 않습니다.
- **주문(Order)**: 주문 아이템 목록(상품 id, 이름, 가격, 수량) + 총액 +
  생성 시각.

세 타입 모두 `packages/types`에서 프론트엔드·백엔드가 함께 정의를
공유합니다.

## 일반 키오스크 기능 청사진 (참고용)

일반적인 무인 주문 키오스크 시스템이 보통 갖추는 기능을 프론트엔드/관리자
/백엔드로 나눠 정리한 청사진입니다. ✅는 이 프로젝트에 이미 구현된 기능,
⬜는 아직 없는 기능입니다. **전부 다 만들겠다는 확정 목록이 아니라, 향후
범위를 논의할 때 빠뜨리기 쉬운 항목을 확인하는 체크리스트**입니다. 실제
작업 우선순위는 [[개발계획서]]의 로드맵에서 정합니다.

### 프론트엔드 (고객 화면)

- ⬜ 대기 화면(Attract screen) — 미조작 시 프로모션/메뉴 슬라이드 노출
- ⬜ 세션 타임아웃 — 일정 시간 미조작 시 화면·장바구니 자동 초기화
- ⬜ 언어 선택 / 다국어 지원 (현재 한국어만 지원)
- ✅ 메뉴 카테고리별 조회 (전체/커피/에이드/디저트)
- ⬜ 메뉴 검색
- ⬜ 상품 옵션 선택 (사이즈, HOT/ICE, 시럽·샷 추가 등 커스터마이징)
- ⬜ 추천/세트 메뉴, 업셀 제안
- ✅ 장바구니 담기 / 수량 자동 증가
- ⬜ 장바구니에서 수량 개별 조절·삭제 (현재는 클릭으로 수량 증가만 가능)
- ⬜ 매장 내(Dine-in) / 포장(Takeout) 선택
- ⬜ 테이블 번호 입력 (매장 내 서빙용)
- ⬜ 쿠폰/프로모션 코드 적용
- ⬜ 멤버십·포인트 조회/적립/사용
- ✅ 주문 총액 계산
- ⬜ 결제 수단 선택 및 결제 진행 화면 (카드/간편결제)
- ✅ 주문 제출
- ⬜ 주문 완료 화면 — 주문번호, 예상 대기 시간
- ⬜ 영수증 출력 여부 선택 (출력/미출력/모바일 발송)
- ⬜ 접근성 대응 (음성 안내, 화면 확대, 저상 배치 등)
- ⬜ 관리자 모드 진입 (숨김 제스처 또는 PIN)

### 관리자 / 백오피스 화면

- ⬜ 관리자 로그인/인증, 역할 구분(점주/직원)
- ✅ 메뉴 등록
- ✅ 메뉴 삭제
- ⬜ 메뉴 수정, 품절 처리
- ⬜ 옵션·조합(사이즈/시럽 등) 관리
- ⬜ 카테고리 관리 (현재 카테고리는 코드에 고정된 enum)
- ⬜ 프로모션/쿠폰 관리
- ⬜ 주문 내역 조회·검색·필터, 주문 상태 변경
- ⬜ 매출/통계 대시보드 (일별 매출, 인기 메뉴 등)
- ⬜ 재고 관리
- ⬜ 대기 화면 배너/공지 관리
- ⬜ 여러 대의 키오스크 원격 설정/모니터링 (다중 매장으로 확장 시)

### 백엔드 / 인프라

- ✅ 상품 CRUD API (`/api/products`)
- ✅ 주문 생성 API (`/api/orders`)
- ⬜ 주문 상태 전이 API (접수 → 준비중 → 완료 → 픽업/서빙)
- ⬜ 관리자 인증/인가(세션 또는 JWT), 감사 로그
- ⬜ 결제 게이트웨이 연동 (PG사 API, 카드 리더 하드웨어, 웹훅 콜백 처리).
  결제 수단 정보 자체는 서버에 저장하지 않는 것이 원칙
- ⬜ 영수증/주방 프린터 연동
- ⬜ 실시간 주방 디스플레이(KDS) 연동 — 주문 발생 시 WebSocket 등으로 즉시
  반영
- ⬜ 쿠폰/프로모션 검증 API
- ⬜ 멤버십·포인트 API
- ⬜ 매출/통계 집계 API
- ⬜ 오프라인 대응 — 네트워크 단절 시 로컬 큐잉 후 재동기화
- ⬜ 다중 매장/다중 키오스크 지원 (매장 단위 데이터 분리)
- ⬜ 모니터링·로깅, 장애 알림

## 알려진 제약 / 리스크

- 관리자 페이지가 무인증 상태라 URL을 아는 누구나 메뉴를 추가/삭제할 수
  있습니다. 실제 운영 전 인증 도입이 필요합니다.
- 백엔드가 요청 바디를 Mongoose 스키마의 `required`/`enum` 검증에만
  의존하고 있어, 검증 실패 시 사용자에게 구체적인 원인이 전달되지
  않습니다.
