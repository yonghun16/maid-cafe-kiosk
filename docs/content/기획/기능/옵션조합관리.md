## 개요
처음엔 "옵션 그룹/옵션 항목을 별도 화면에서 등록하고, 상품마다 어떤
그룹을 연결할지 매핑하는" 형태를 예상했지만, 실제 요청은 "메뉴를 추가할
때 그 메뉴만의 옵션을 바로 추가할 수 있게 해달라"는 더 단순한 것이었고,
그렇게 범위를 좁혀 구현했습니다.

원래 "샷 추가"(+700원), "온도(HOT/ICE)", "마법의 주문"(모에모에뀽 등
4항목)은 전부 매장 전체 고정 옵션이었는데, "메뉴에서 기본 옵션이
아니라 필요할 때만 추가하는 옵션이었으면 좋겠다"는 요청으로 세 옵션
모두 메뉴별로 관리자가 켜는 방식으로 옮겨왔습니다. 그 과정에서 한 번은
온도/마법의 주문도 "메뉴 옵션"(이름+추가금 자유 등록, 여러 개 동시
선택 가능한 체크박스)으로 합쳐졌었는데, **온도와 마법의 주문은 원래
"여러 항목 중 딱 하나만 고르는" 성격이라 체크박스로는 어색하다**는
피드백으로 다시 분리해, 지금은 옵션이 **두 트랙**으로 나뉩니다.

### 트랙 1 — 콤보박스 옵션 (온도 / 마법의 주문)
- 관리자가 메뉴 추가/수정 폼에서 "온도 옵션 (HOT/ICE)", "마법의 주문
  옵션" 체크박스로 그 메뉴에 노출할지만 켜고 끕니다
  (`Product.hasTemperatureOption`/`hasMagicSpellOption`).
- 켜져 있으면 고객 화면에는 그중 하나만 고르는 UI가 나타납니다 —
  **온도는 HOT/ICE 버튼 2개**(이미 고른 걸 다시 누르면 선택 해제),
  **마법의 주문은 드롭다운**(모에모에뀽/오이시쿠나레/냥냥쿵/
  하피네스차지! 중 하나, "선택 안 함" 포함). 온도를 드롭다운으로도
  만들어봤지만, 버튼으로 바로 눌러 고르는 예전 방식이 더 낫다는
  피드백으로 버튼으로 되돌렸습니다. 마법의 주문 드롭다운은 처음엔
  네이티브 `<select>`였는데, 모바일에서 OS 기본 선택 UI(iOS 휠,
  안드로이드 바텀시트 등)로 열려 앱 디자인과 안 어울린다는 피드백으로
  같은 페이지 레이어 위에 뜨는 커스텀 드롭다운(`shared/ui/Dropdown`)
  으로 바꿨습니다.
- 두 옵션 다 항목 이름은 고정이고 가격 영향도 없습니다 — 관리자가
  바꿀 수 있는 건 "이 메뉴에 보여줄지 여부"뿐입니다.
- **온도를 "ICE"로 고르면 얼음양 하위 옵션이 추가로 나타납니다** —
  "적게"/"적당"/"많이" 버튼 3개(온도 버튼과 같은 스타일, 하늘색 계열로
  구분). "HOT"을 고르거나 온도 선택을 아예 해제하면 얼음양 선택지도
  같이 사라지고 초기화됩니다. 이 하위 옵션은 별도 관리자 토글이
  없습니다 — 온도 옵션이 켜진 메뉴라면 항상 ICE에 딸려 나옵니다.

### 트랙 2 — 메뉴 옵션 (그 외 나머지)
- "샷 추가"처럼 항목이 하나뿐이거나, 여러 개를 동시에 골라도 자연스러운
  옵션은 예전처럼 이름+추가금을 자유롭게 등록하는 체크박스 목록입니다
  (`Product.options`). "+ 옵션 추가"로 직접 입력하거나, "+ 샷 추가
  (+700원)" 같은 자주 쓰는 옵션 칩을 눌러 한 번에 추가할 수 있습니다.

옛 방식으로 매장 전체 고정 옵션이던 시절에 생성된 주문의
`hasExtraShot` 필드는 과거 데이터 표시용으로만 남아있습니다(2026-09-10에
운영 DB의 과거 주문을 전부 삭제해서, 실제로 남아있는 과거 데이터는
없습니다). 반면 `temperature`/`magicSpell`은 트랙 1로 다시 살아나면서
**지금도 실제로 쓰이는 필드**입니다. 자세한 이전 히스토리는
[[상품옵션선택]] 참고.

## 동작 방식
- **콤보박스 옵션(온도/마법의 주문)**: 메뉴 추가/수정 폼 상단의
  체크박스 두 개로 각각 켜고 끕니다. 저장하면 `Product`에
  `hasTemperatureOption`/`hasMagicSpellOption` boolean으로 저장됩니다.
  고객이 값을 고르면 `CartItem.temperature`/`iceAmount`/`magicSpell`에
  담기고, 가격에는 영향 없이 `cartItemId`(`"<id>:temp:ICE:ice:적게"`,
  `"<id>:spell:모에모에뀽"`)에 반영돼 다른 조합은 장바구니에서 다른
  줄로 취급됩니다.
- **메뉴 옵션(이름+추가금)**: "+ 옵션 추가"를 누르면 입력 줄이 하나
  생기고, 여러 개를 자유롭게 추가·삭제할 수 있습니다. 이름을 비워둔
  줄은 저장 시 자동으로 제외됩니다. "+ 샷 추가 (+700원)" 같은 프리셋
  칩을 누르면 정해진 이름+가격 그대로 목록에 추가되고, 이미 추가된
  옵션은 칩 목록에서 사라집니다(중복 방지).
- 저장하면 `Product.options`에 `{ name, price }` 배열로 저장됩니다.
  수정 폼은 옵션 목록을 항상 전체 다시 보내므로, 옵션을 전부 지우고
  저장하면 실제로 전부 삭제됩니다(재고 수량처럼 "생략하면 기존 값
  유지"가 아님). `hasTemperatureOption`/`hasMagicSpellOption`도 수정
  폼에서 항상 현재 체크 상태 그대로 덮어씁니다.
- 고객 화면에서 메뉴를 클릭하면, 콤보박스 옵션이 켜져 있으면 드롭다운이,
  메뉴 옵션이 등록돼 있으면 체크박스 목록이 나타납니다(둘 다 없으면
  옵션 영역 자체가 안 보임). 메뉴 옵션은 여러 개를 동시에 선택할 수
  있고, 선택한 옵션의 추가금이 모두 합산돼 최종 가격에 반영됩니다.
- 장바구니에 담을 때 선택한 값들(`temperature`, `magicSpell`,
  `selectedOptions`)을 그대로 스냅샷으로 남깁니다. 이후 관리자가 메뉴
  옵션을 수정/삭제해도 이미 담긴 장바구니나 지난 주문 내역은
  영향받지 않습니다.
- 주문 내역/주방 화면([[주문내역조회]])에도 온도/마법의 주문/커스텀
  옵션이 전부 배지로 표시돼, 주방에서 어떤 옵션이 추가됐는지 바로
  확인할 수 있습니다.

## 관련 코드
- `packages/types`의 `ProductOption`(`{ name, price }`),
  `Product.options`/`hasTemperatureOption`/`hasMagicSpellOption`,
  `ProductInput`도 동일 필드, `CartItem.temperature`/`iceAmount`/
  `magicSpell`/`selectedOptions`, `OrderItem.temperature`/`iceAmount`/
  `magicSpell`/`selectedOptions`(`hasExtraShot`은 과거 호환용으로만 남음)
- `apps/backend/src/models/Product.ts` (`options` 배열 필드,
  `hasTemperatureOption`/`hasMagicSpellOption` boolean 필드)
- `apps/backend/src/models/Order.ts` (`items.temperature`(`enum:
  ['HOT','ICE']`)/`iceAmount`(`enum: ['적게','적당','많이']`)/
  `magicSpell`/`selectedOptions` 필드)
- `apps/backend/src/routes/products.ts` (`POST/PUT /api/products`가
  `options`/`hasTemperatureOption`/`hasMagicSpellOption`을 저장. 수정
  시엔 항상 덮어써서 폼에서 끈 옵션이 실제로 꺼지게 함)
- `apps/backend/src/routes/orders.ts` — `iceAmount`는 상품이 아니라
  주문 아이템에만 있는 필드라 `POST /api/orders`가 `req.body.items`를
  그대로 저장하면서 함께 반영됨
- `apps/frontend/src/entities/product/model/optionConstants.ts`
  (`TEMPERATURE_OPTIONS`, `MAGIC_SPELL_OPTIONS`, `ICE_AMOUNT_OPTIONS`
  — 콤보박스 옵션의 고정 선택지)
- `apps/frontend/src/entities/product/ui/ProductOptionsEditor.tsx`
  (온도/마법의 주문 체크박스 + 메뉴 옵션 이름/추가금 입력 줄, 메뉴
  추가/수정 폼 양쪽에서 사용. `PRESET_OPTIONS`는 이제 "샷 추가"만 남음)
- `apps/frontend/src/widgets/add-product-form/ui/AddProductForm.tsx`,
  `apps/frontend/src/widgets/manage-product-list/ui/EditProductForm.tsx`
  (`ProductOptionsEditor` 사용, 이름 없는 옵션 줄은 저장 전 필터링)
- `apps/frontend/src/entities/product/ui/ProductCard.tsx` (옵션 모달 —
  `product.hasTemperatureOption`이 켜져 있으면 HOT/ICE 버튼 2개 +
  ICE를 골랐을 때만 얼음양 버튼 3개, `product.hasMagicSpellOption`이
  켜져 있으면 마법의 주문 `shared/ui/Dropdown`, `product.options`는
  체크박스로 렌더링)
- `apps/frontend/src/shared/ui/Dropdown.tsx` (네이티브 `<select>`
  대체용 커스텀 드롭다운 — 버튼 클릭 시 같은 페이지 레이어 위에
  옵션 목록을 띄움, 바깥 클릭 시 닫힘. 도메인 지식 없는 순수 UI라
  `shared/ui`에 위치, 마법의 주문 외에 다른 곳에서도 재사용 가능)
- `apps/frontend/src/features/cart/model/store.ts` (`addToCart`가
  `temperature`/`iceAmount`/`magicSpell`/`selectedOptions`를 받아
  `cartItemId`에 반영, 가격에는 `selectedOptions`만 합산)
- `apps/frontend/src/widgets/order-summary/ui/OrderSummary.tsx`,
  `apps/frontend/src/entities/order/ui/OrderCard.tsx` (온도/얼음양/
  마법의 주문/커스텀 옵션을 배지로 표시)

## 범위 밖
- 온도/마법의 주문 외에 "여러 항목 중 하나만 고르는" 옵션을 관리자가
  직접 새로 정의하는 기능 — 지금은 이 두 가지만 코드에 고정돼 있고,
  세 번째 콤보박스 옵션이 필요해지면 그때 일반화를 검토합니다.
- 메뉴 옵션(이름+추가금)을 별도 화면에서 등록하고 여러 메뉴에
  재사용하는 "옵션 그룹" 모델 — 지금은 메뉴마다 완전히 독립적으로
  등록합니다.
- 옵션별 재고 추적, 옵션 조합에 따른 품절 처리.
