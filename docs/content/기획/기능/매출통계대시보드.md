## 개요
매장 운영 의사결정을 돕기 위해 매출 추이와 인기 메뉴를 보여주는
대시보드입니다. "조회할 지표 범위"가 열린 질문이었는데, **월별 추이
차트 + 선택한 달의 메뉴별 판매 순위**로 범위를 정했습니다(일별 집계,
카테고리별 집계 등은 이번 범위에 넣지 않음).

## 동작 방식
- `/admin`의 **"판매 통계" 탭**에 두 블록이 있습니다.
  1. **월별 판매량 추이**: 최근 6개월을 막대 차트로 보여줍니다. 막대
     높이는 판매량(`totalQuantity`, 해당 달 모든 주문의 아이템 수량
     합)을 기준으로 하고, 매출(`totalRevenue`)은 막대 아래 작은
     텍스트로 함께 보여줍니다. 주문이 없는 달도 0으로 채워 넣어
     차트가 끊기지 않습니다.
  2. **메뉴별 판매 순위**: 막대를 클릭해 고른 달의 메뉴별 판매량/매출
     순위표입니다(판매량 내림차순). 기본으로 가장 최근 달이 선택돼
     있습니다.
- **집계 기준**: 주문 생성 시점(`Order.createdAt`)을 KST로 환산한
  연-월로 묶습니다. 완료 여부(`isCompleted`)와 무관하게 **생성된 모든
  주문을 판매로 집계**합니다 — 이 앱에는 주문 취소 개념이 없고, 완료
  처리는 "주방에서 다 만들어 건넸다"는 뜻이라 매출 집계와는 무관하기
  때문입니다.
- **성능**: 실시간 MongoDB 집계(`$group`/`$unwind`)로 매 요청마다
  계산합니다. 주문량이 아주 많아지면 사전 집계(별도 컬렉션에 배치로
  미리 합산)로 바꿀 수 있지만, 지금 규모(매장 1곳)에서는 실시간
  집계로 충분합니다.
- 차트는 외부 라이브러리 없이 `div` 높이(`style`의 인라인 퍼센트)로
  직접 그렸습니다 — 데이터에 따라 동적으로 계산되는 값이라 Tailwind
  유틸리티 클래스로는 표현할 수 없어, 이 경우엔 예외적으로 인라인
  스타일을 씁니다.

## 관련 코드
- `packages/types`의 `MonthlySalesSummary`, `ProductSalesRanking`
- `apps/backend/src/index.ts` — `GET /api/orders/stats/monthly`(최근
  N개월 추이, 기본 6개월, 없는 달은 0으로 채움),
  `GET /api/orders/stats/monthly/:month`(그 달의 메뉴별 판매 순위),
  둘 다 `requireAdmin`으로 보호. `getLastNMonthLabels`/
  `getKstMonthRange` 헬퍼(KST 기준 월 경계 계산, `getKstStartOfToday`와
  같은 패턴)
- `apps/frontend/src/entities/order/api/orderApi.ts`
  (`getMonthlySalesSummary`, `getProductSalesRanking`)
- `apps/frontend/src/widgets/sales-dashboard/ui/SalesDashboard.tsx`
  (막대 차트 + 순위표, 막대 클릭으로 달 선택)
- `apps/frontend/src/views/admin/ui/AdminPage.tsx` ("판매 통계" 탭)
