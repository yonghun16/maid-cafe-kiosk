## 개요
관리자 화면(`/admin`)의 "주문 내역" 탭에서 들어온 주문을 최신순으로
확인할 수 있습니다. 검색/필터, 주문 상태 변경(접수/준비중/완료 등)은
아직 없어 전체 상태는 작업중입니다.

## 완료: 주문 목록 조회
`/admin`에서 "주문 내역" 탭을 누르면 전체 주문을 최신순으로 보여줍니다.
10초마다 자동으로 갱신되고, "새로고침" 버튼으로 즉시 갱신할 수도
있습니다. 각 주문 카드에는 매장/포장 구분, **주문번호**, 메뉴
이미지·이름·수량, 합계 금액, **날짜+주문 시각**이 표시됩니다. 실시간
푸시(WebSocket) 없이 폴링 방식으로만 구현했습니다 — 더 즉각적인 갱신이
필요해지면 [[실시간주방디스플레이KDS]]로 업그레이드를 검토합니다.

주문번호는 MongoDB의 긴 `_id` 대신, **한국 시간(KST) 기준 당일
자정부터 1번씩 다시 매기는 짧은 번호**입니다(스타벅스 매장 주문번호
방식 — "23번 손님" 처럼 호출하기 좋게). 별도 카운터 컬렉션 없이, 주문
생성 시점에 오늘 자정(KST) 이후 생성된 주문 수를 세어 `+1`한 값을
그대로 저장합니다. 동시에 여러 주문이 들어오면 이론상 번호가 겹칠 수
있지만, 매장 1곳·순차적인 방문 트래픽이라는 현재 규모에서는 감수할
만한 트레이드오프로 판단했습니다.

이 화면은 주로 PC에서 쓴다는 점을 고려해 데스크탑 위주로 만들었습니다
— 목록은 화면 폭에 따라 1~3열 그리드로 배치되고, 글자·이미지 크기를
크게 잡아 멀리서도 알아보기 쉽게 했습니다. 메뉴 관리 탭의 목록도 같은
이유로 이미지/글자 크기를 키웠습니다. 주문 항목에는 상품 자체가 아니라
**주문 시점의 이름/가격/이미지 스냅샷**(`OrderItem`)이 저장되므로,
나중에 상품 이미지가 바뀌거나 상품이 삭제돼도 과거 주문에 찍힌 이미지는
그대로 남습니다.

### 관련 코드
- `apps/backend/src/index.ts` — `GET /api/orders`(`requireAdmin`으로
  보호, 최신순 정렬)
- `apps/frontend/src/entities/order` (`getOrders`, `OrderCard`)
- `apps/frontend/src/widgets/order-list/ui/OrderList.tsx` (10초 폴링,
  수동 새로고침, 반응형 그리드)
- `apps/frontend/src/views/admin/ui/AdminPage.tsx` ("메뉴 관리"/"주문
  내역" 탭 전환)
- `apps/backend/src/index.ts` — `POST /api/orders`의
  `getKstStartOfToday`/`orderNumber` 계산 로직
- `packages/types`의 `Order`(`orderNumber` 필드), `OrderItem`
