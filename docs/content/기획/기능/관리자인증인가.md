## 개요
[[관리자로그인인증]]이 프론트엔드 로그인 화면 관점이라면, 이 문서는
서버 측에서 관리자 전용 쓰기 API를 세션 기반으로 인증/인가하는
메커니즘입니다. 감사 로그는 이번 구현 범위에 포함하지 않았습니다.

## 동작 방식
`POST /api/admin/login`이 `ADMIN_PASSWORD` 환경변수 값과 요청 비밀번호를
`timingSafeEqual`로 비교하고, 일치하면 `express-session` 세션에
`isAdmin: true`를 기록합니다. 세션은 `connect-mongo`로 기존
MongoDB(`MONGO_URI`)에 저장됩니다. `GET /api/admin/session`은 현재
세션의 인증 여부만 반환하고, `POST /api/admin/logout`은 세션을
파기합니다. `requireAdmin` 미들웨어가 세션의 `isAdmin` 값을 확인해 관리자 전용
쓰기 API(카테고리/상품/광고의 등록·수정·삭제·순서변경, 이미지 업로드)와
관리자 전용 조회 API(주문 목록·완료 처리, 매출 통계 2종)를 보호하며,
인증 없이 호출하면 401을 반환합니다. 고객이 직접 쓰는 `GET
/api/products`·`GET /api/categories`·`GET /api/ads`·`POST
/api/orders`는 의도적으로 무인증 공개입니다. 프론트엔드(Vercel)와 백엔드(Render)가
다른 오리진이라 CORS는 `FRONTEND_ORIGIN` 하나만 명시적으로 허용하고
`credentials: true`로 세션 쿠키를 주고받습니다. Render는 앞단
프록시(Cloudflare)가 HTTPS를 종료하고 내부적으론 HTTP로 전달하므로,
`app.set('trust proxy', 1)`을 설정해 Express가 `X-Forwarded-Proto`를
신뢰하게 했습니다 — 이게 없으면 `cookie.secure: true`인 세션 쿠키가
Set-Cookie 헤더에 아예 실리지 않아, 로그인은 성공하지만 이후 요청에서
세션이 인식되지 않는 문제가 있었습니다.

## 관련 코드
- `apps/backend/src/index.ts` (세션 미들웨어, `trust proxy` 설정, CORS
  설정, 라우터 마운트)
- `apps/backend/src/routes/adminAuth.ts` — `POST /api/admin/login`,
  `GET /api/admin/session`, `POST /api/admin/logout`
- `apps/backend/src/middleware/requireAdmin.ts`
- `apps/backend/src/types/session.d.ts` (세션 타입 확장)
- 환경변수: `ADMIN_PASSWORD`, `SESSION_SECRET`, `FRONTEND_ORIGIN`
