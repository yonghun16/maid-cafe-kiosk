## 개요
키오스크(`/`)에 처음 들어오면 메뉴 목록 대신 "매장에서 드시나요 포장해
드릴까요?" 선택 화면이 먼저 뜹니다. 선택해야만 메뉴 목록으로 넘어갈 수
있고, 선택한 값은 주문에 그대로 포함됩니다.

## 동작 방식
`features/order-type`의 Zustand 스토어가 `orderType`(`'dine-in' |
'takeout'` | `null`)을 들고 있습니다. `orderType`이 `null`이면
`HomePage`가 메뉴 목록 대신 `OrderTypeSelect` 화면을 보여주고, "매장에서"
또는 "포장" 버튼을 누르면 값이 채워지며 메뉴 목록(`ProductList` +
`OrderSummary`)으로 전환됩니다. 주문 목록 패널에는 현재 선택이 작게
표시됩니다. "주문하기"를 눌러 주문이 성공하면 다음 손님을 위해
`orderType`이 다시 `null`로 초기화되어 선택 화면으로 돌아갑니다.
선택값은 `POST /api/orders` 요청의 `orderType` 필드로 함께 전송되어
주문 데이터에 저장됩니다.

매장 내 선택 시 테이블 번호를 받는 흐름은 필요 없다고 판단해 백로그에서
제외했습니다.

**중간에 매장/포장을 바꾸는 버튼**: 손님이 메뉴를 고르다가 매장↔포장을
바꾸고 싶을 수 있는데, 처음엔 주문을 완료해야만(또는 새로고침해야만)
선택 화면으로 돌아갈 수 있었습니다. "중간에 처음 화면으로 돌아가는
버튼이 필요할 것 같다"는 요청으로, `HomePage` 최상단에 현재 선택
("🍽️ 매장"/"🥡 포장")을 보여주는 작은 "↩ 처음으로" 버튼을 항상
띄워뒀습니다. 눌러도 `orderType`만 `null`로 초기화될 뿐 장바구니
(`features/cart`)는 그대로 남아있어서, 다시 매장/포장을 고르면 담아둔
메뉴가 그대로 이어집니다.

## 관련 코드
- `apps/frontend/src/features/order-type` (`useOrderTypeStore`)
- `apps/frontend/src/widgets/order-type-select/ui/OrderTypeSelect.tsx`
- `apps/frontend/src/views/home/ui/HomePage.tsx` (선택 전/후 화면 전환,
  화면 상단의 "↩ 처음으로" 버튼 — `resetOrderType` 호출)
- `apps/frontend/src/widgets/order-summary/ui/OrderSummary.tsx`
  (선택값 표시, 주문 성공 시 초기화)
- `apps/frontend/src/features/cart/model/store.ts` (`submitOrder`가
  `orderType`을 받아 요청에 포함)
- `apps/backend/src/models/Order.ts` (`orderType` 필드),
  `apps/backend/src/index.ts` — `POST /api/orders`
- `packages/types`의 `OrderType`, `Order`, `CreateOrderInput`
