## 개요
"메뉴를 선택하면 옵션을 선택할 수 있게 해달라"는 요청으로 시작했고,
처음엔 **매장 전체에 고정으로 적용되는 옵션**(샷 추가, 마법의 주문,
온도)만 넣는 걸로 범위를 좁혔습니다. 이후 "메뉴마다 다른 옵션을 등록할
수 있게 해달라"는 요청으로 [[옵션조합관리]](메뉴별 자유 옵션)가
추가되면서, **"샷 추가"와 "온도(HOT/ICE)"가 차례로 매장 전체 고정
옵션에서 빠지고 메뉴별 커스텀 옵션으로 옮겨졌습니다** — 모든 메뉴에
기본으로 뜨던 체크박스/토글 버튼이 없어지고, 이제는 관리자가 필요한
메뉴에만 "샷 추가", "HOT", "ICE" 같은 이름의 옵션을 직접 추가해야
고객 화면에 나타납니다. **지금 매장 전체 고정 옵션으로 남은 건 "마법의
주문" 하나뿐**입니다.

**마법의 주문**은 메이드 카페에서 서빙할 때 직원이 함께 외쳐주는 주문
(呪文)을 고객이 미리 고르는, 메이드 카페 컨셉의 재미 옵션입니다. 실제
음료/음식 구성이나 가격에는 영향이 없고, "모에모에뀽", "오이시쿠나레",
"냥냥쿵", "하피네스차지!" 네 항목 중 하나를 드롭다운으로 고릅니다
(선택 안 함도 가능). 모든 메뉴에 계속 고정으로 노출됩니다.

## 동작 방식
- 고객 화면에서 메뉴 카드를 클릭하면 예전처럼 바로 장바구니에 담기는
  대신, **옵션 선택 모달**(`shared/ui/Modal` 재사용)이 뜹니다. 모달에는
  왼쪽에 메뉴 사진, 오른쪽에 이 메뉴에 등록된 커스텀 옵션이 있으면
  체크박스 목록(없으면 이 영역 자체가 안 보임, [[옵션조합관리]] 참고),
  "마법의 주문" 드롭다운이 차례로 있고, 아래에 옵션 반영된 최종 가격과
  "담기" 버튼이 있습니다. 처음엔 사진을 위, 옵션을 아래에 뒀는데 사진이
  가로로 넓은 틀(`h-40 w-full`)에 눌려 잘려 보였습니다 — 사진을
  **왼쪽에, 상품 카드와 같은 3:4 비율 그대로** 두고 옵션을 오른쪽에
  배치해 해결했습니다.
- **장바구니 줄 구분**: 같은 메뉴라도 옵션 조합(마법의 주문 선택값 +
  커스텀 옵션 선택)이 다르면 다른 줄로 취급해야 해서, 상품 `_id`와
  별개로 장바구니 전용 `cartItemId`를 도입했습니다(`makeCartItemId`가
  `"<productId>"`, `"<productId>:spell:모에모에뀽"`,
  `"<productId>:opts:샷 추가,ICE"`처럼 선택된 옵션만 순서대로 이어붙여
  만듦). 수량 증감/삭제 버튼도 전부 `cartItemId` 기준으로 동작합니다.
- **가격 처리**: 커스텀 옵션 추가금만 장바구니에 담는 시점에 이미
  상품 가격에 더해서 저장합니다(`CartItem.price` = 기본가 + 선택한
  옵션들의 추가금 합). 마법의 주문은 가격에 영향이 없습니다. 주문
  생성 시 가격이 그대로 `OrderItem.price`로 전달되므로, 총액 계산이나
  [[매출통계대시보드]]의 매출 집계(`item.price * item.quantity` 합산)도
  별도 처리 없이 옵션 추가금까지 자동으로 포함됩니다.
- **주문 내역/주방 화면 표시**: `OrderItem.magicSpell`/`selectedOptions`
  가 저장되고, 주문 내역 카드([[주문내역조회]])와 장바구니 목록 양쪽에
  "🪄 (고른 주문)" 표시, 선택한 커스텀 옵션 이름 배지가 붙어서 주방에서
  놓치지 않게 했습니다. 처음엔 메뉴 이름과 옵션 배지를 하나의
  `truncate` 문단에 같이 넣었는데, 이름이 조금만 길어져도 그 뒤에
  붙는 옵션 배지가 통째로 잘려서 안 보이는 문제가 있었습니다(주방
  화면에서 실제로 발견) — 이름은 그대로 두고 옵션 배지들은
  `flex-wrap`으로 줄바꿈되는 별도 영역으로 분리해 해결했습니다.
- **`hasExtraShot`/`temperature` 필드는 과거 호환용으로만 남음**: "샷
  추가"/"온도(HOT/ICE)"가 매장 전체 고정 옵션이던 시절에 생성된
  주문에는 `OrderItem.hasExtraShot`/`temperature`가 저장돼 있어,
  `OrderCard`가 그 값을 그대로 읽어 배지를 표시합니다. 이후로 생성되는
  주문은 이 필드들을 쓰지 않고, "샷 추가"나 "HOT"/"ICE"를 골랐다면
  `selectedOptions`에 담깁니다. (참고: 2026-09-10에 운영 DB의 과거
  주문 데이터를 전부 삭제해서, 실제로는 이 호환 경로를 거칠 기존
  데이터가 남아있지 않습니다.)
- **`OrderItem._id` 노출**: MongoDB가 주문의 하위 문서(각 아이템)마다
  자동으로 `_id`를 부여하는데, 원래 타입에는 선언돼 있지 않았습니다.
  같은 상품이 옵션만 다르게 여러 줄로 들어간 주문에서 `productId`만으로는
  React 리스트 key가 겹칠 수 있어서, 이번에 `OrderItem._id`(선택
  필드 — 주문 생성 요청 바디에는 없고 저장된 주문 응답에만 있음)를
  타입에 추가하고 주문 내역 카드의 key로 씁니다.

## 관련 코드
- `packages/types`의 `CartItem.cartItemId`/`magicSpell`/`selectedOptions`,
  `OrderItem.magicSpell`/`selectedOptions`/`_id`(선택),
  `OrderItem.hasExtraShot`/`temperature`(과거 호환용, 더 이상 새로
  쓰이지 않음)
- `apps/backend/src/models/Order.ts` (`items.magicSpell`/
  `selectedOptions` 필드, `hasExtraShot`/`temperature`는 과거 데이터
  호환용으로만 남김)
- `apps/frontend/src/entities/product/model/optionConstants.ts`
  (`MAGIC_SPELL_OPTIONS` 4항목만 남음 — "샷 추가"/"온도(HOT/ICE)"는
  더 이상 여기 없고 메뉴별 커스텀 옵션으로 등록)
- `apps/frontend/src/entities/product/ui/ProductCard.tsx` (클릭 시
  옵션 모달 — 왼쪽 사진(3:4)/오른쪽 옵션 레이아웃, 커스텀 옵션
  체크박스, 마법의 주문 드롭다운, "담기" 버튼)
- `apps/frontend/src/features/cart/model/store.ts` (`makeCartItemId`,
  `addToCart`가 옵션을 받아 가격/줄 구분에 반영, 수량 증감/삭제가
  `cartItemId` 기준으로 동작)
- `apps/frontend/src/widgets/order-summary/ui/OrderSummary.tsx`
  (장바구니 목록에 "🪄 (마법의 주문)"/커스텀 옵션 표시)
- `apps/frontend/src/entities/order/ui/OrderCard.tsx` (주문 내역/주방
  화면에 "🪄 (마법의 주문)"/커스텀 옵션 배지 표시, 과거 주문의
  `hasExtraShot`/온도 배지도 계속 표시)
