# 관리자 인증 추가

## Overview

`/admin` 화면이 현재 완전히 무인증 상태다. URL만 알면 누구나 메뉴를
등록·삭제할 수 있어([[기획서]]의 "알려진 제약" 참고), 실제 매장 운영
전 반드시 막아야 하는 최우선 로드맵 항목([[개발계획서]] 1번)이다.

이 스펙은 "관리자만 `/admin`과 그 하위 API(`POST/DELETE
/api/products`)를 쓸 수 있게 최소 접근 제어를 추가"하는 것을 목표로
한다. 역할 구분(점주/직원), 다중 관리자 계정 관리 같은 확장은 이번
스코프에 넣지 않는다 — 우선 "관리자 vs 비관리자" 한 단계만 가른다.

## Design

**결정 필요 (구현 착수 전 확정할 것)**
- 인증 방식: (a) 공유 비밀번호 하나로 세션 발급 (b) 계정별 로그인
  (아이디/비번) 중 무엇으로 할지. 매장이 1곳, 관리자 소수라는 현재
  규모를 고려하면 (a)로 시작하고 필요해지면 (b)로 확장하는 쪽을
  권장.
- 세션 유지 방식: httpOnly 쿠키 기반 세션 vs JWT. 백엔드가 Express +
  MongoDB이므로 서버 세션(예: `express-session` + Mongo 세션
  스토어)이 JWT 발급/검증 로직을 새로 추가하는 것보다 구현 부담이
  적다.

**영향 범위**
- 백엔드: 로그인 API(예: `POST /api/admin/login`), 인증 미들웨어를
  만들어 `POST/DELETE /api/products`에 적용. `GET /api/products`,
  `POST /api/orders`(고객용)는 그대로 무인증 유지.
- 프론트엔드: `/admin` 진입 시 미인증이면 로그인 폼으로 리다이렉트.
  FSD상 신규 `features/admin-auth`(로그인 폼 + 인증 상태) 슬라이스로
  분리하고, 기존 `features/product-management`는 그대로 둔다.
- 환경변수: 관리자 비밀번호/세션 시크릿을 `.env`와 배포 환경(Render)
  양쪽에 추가해야 함 — [[개발계획서]]의 환경변수 목록에도 반영 필요.

## Notes

- 역할 구분(점주/직원), 감사 로그, 다중 관리자 계정은 이번 스코프
  밖 — 필요해지면 별도 스펙으로 분리.
- **운영 배포 미완료**: Render에 `ADMIN_PASSWORD`/`SESSION_SECRET`/
  `FRONTEND_ORIGIN` 환경변수를 아직 등록하지 않았습니다. 등록 전까지는
  운영 환경에서 로그인 자체가 안 되지만(로그인 API가 500 반환), 쓰기 API
  보호는 그대로 유지됩니다(fail-closed). 사용자가 Render 대시보드에서
  직접 등록해야 합니다.
- 백엔드 curl 테스트(로그인/세션조회/쓰기API차단/로그아웃)는 전부 통과.
  프론트엔드는 타입체크·프로덕션 빌드 통과와 SSR 출력 확인까지만
  했고, 브라우저에서의 실제 클릭 인터랙션(로그인 폼 제출 → 화면 전환)은
  검증하지 못했습니다 — Chrome 확장 연결이 이 세션에서 보류됨.

  "알려진 제약", [[개발계획서]]의 완료된 마일스톤/로드맵.
